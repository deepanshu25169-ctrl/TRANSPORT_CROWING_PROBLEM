# Actual validation results

Train: 2026-10-01 … 2026-10-21. Test: 2026-10-22 … 2026-10-31.
Full output: `output/validation.json` (generated by `python3 scripts/validate.py`).

## Held-out segment error (recorded passengers per segment)

| Model | n segment observations | MAE | RMSE |
|---|---:|---:|---:|
| Pattern + day type + time bin, shrunk to route median (14-day window, k=600) | 2,383,514 | **0.459** | **1.025** |
| Baseline: typical route load, no time of day | 2,383,514 | 0.461 | 1.054 |

The model now beats the route-only baseline on both MAE (delta `-0.0023`) and RMSE.
The gain is modest by design: fine bins are shrunk toward the route median using a strength
chosen on earlier weeks only (candidates 0, 5, 15, 40, 100, 250, 600, 1500; backtest MAE
0.485 → 0.462, optimum at 600). Do not expect large point-forecast gains from sparse tickets.

## What the ticket data supports

- Relative recorded demand by route pattern, direction, day type and segment.
- Comparison of scheduled alternatives using recorded loads on identical stretches.
- Identification of uncertainty: coverage gaps, ambiguous names, unknown vehicle models.

## What it does not support

- Total onboard passengers (ticket coverage q is unknown; no citywide multiplier applied).
- Physical seat availability, standing comfort or a cross-route physical comfort ranking.
- Whether an unobserved scheduled departure actually operated.
- Credible capacity mode until a real fleet register populates a capacity map.
